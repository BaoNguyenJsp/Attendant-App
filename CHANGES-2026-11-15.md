## 1. Sibling families for students and Huynh trưởng

### Rules
| Status change | What happens to the sibling family |
|---|---|
| → **Ngưng hoạt động** | The student leaves the family. A family left with one member ends. |
| → **Đã tốt nghiệp** | Xứ đoàn only, and only for a student of the **last class** (by order, today *Dự bị trưởng 2*). A new Huynh trưởng account is created and takes the student's place in the family. The status is then locked. |
| Student deleted | Removed from the family; if they were a graduate, their Huynh trưởng account stays in it. |
| Huynh trưởng deleted | Removed from the family; a family left with one member ends. |

The new Huynh trưởng account on graduation:
- name and saint name copied from the student;
- status **Hoạt động**;
- email `graduate-<studentId>-<random>@pending.invalid` — it can never sign in with Google, so the account is safe until Xứ đoàn sets the real email;
- member of the class group of **Chiên Con**.

Old data is not changed: students already *Ngưng hoạt động* or *Đã tốt nghiệp* stay in their families (hidden from view), and earlier graduates get no account.

### Data
New table `SiblingUsers (UserId PK, StudentId UNIQUE NULL, FamilyId NULL)` — see `schema.sql` and
`migrations/2026-11-15-sibling-users.sql` (adds the empty table only).

| Row | Meaning |
|---|---|
| `(61, 551, 7)` | Huynh trưởng #61 was student #551 and is in family #7 |
| `(61, 551, NULL)` | graduate without siblings (link only) |
| `(14, NULL, 7)` | Huynh trưởng #14, never a student, in family #7 |

Students stay in `SiblingMembers`. A graduate's student row leaves `SiblingMembers` and the user row carries the
family, so the person is counted once. A family needs two members, students and Huynh trưởng together.

### Who edits siblings
- **Student form** (Thiếu nhi page): adds / removes students. Huynh trưởng in the family are shown without a remove
  button, and the server keeps them even if the request leaves them out.
- **Huynh trưởng form** (Quản trị page, and Huynh trưởng page for BQT ngành): adds / removes students and Huynh trưởng.
  The search covers every active student and every active Huynh trưởng (not only the sector in view).
- **Rời nhóm** button on the Huynh trưởng forms: takes only that Huynh trưởng out of the family at once; the other
  members stay together (action `leaveSiblingFamily`; Xứ đoàn for anyone, BQT ngành for their sector).

### Display
- Column **Anh/Chị/Em** on the Thiếu nhi list, Quản trị › users and the Huynh trưởng page.
- Only active members are shown; Huynh trưởng as a red badge; a graduate appears once, as their account.
- Up to 3 siblings in the cell; past that the first 2 and a **+N khác** button that opens the full list in a popup.

## 2. Tables

- Action buttons are icons: ✏️ Cập nhật, 🗑️ Xóa (title / aria-label name the action). Thiếu nhi list, Quản trị users /
  groups / classes, Huynh trưởng list.
- The action column stays pinned on the right when a table scrolls sideways (same tables).
- Person names no longer wrap: Thiếu nhi, Học tập, Chuyên cần, Huynh trưởng, Quản trị.
- The sibling cell is capped at about 20rem so it does not squeeze the other columns.

API changes: `listStudents` no longer returns `siblingIds`; families come from `getFamilies`
(`{ members: [{ key, familyId, name, classId, active, teacher }], graduates: { s551: 'u61' } }`).
`saveStudent`, `saveUser`, `saveSectorUser` take `siblings` (keys like `s12`, `u7`) and return the new `families`.

## 4. Deploy (production)

```sh
npx wrangler d1 execute DB --remote --file=migrations/2026-11-15-sibling-users.sql
npm run deploy
```

## 5. Known limits
- The "+N khác" popup uses the native popover API (Chrome/Edge 114+, Safari 17+, Firefox 125+).
- Saving a student and their siblings is two writes (marked `ponytail:` in `students.js`).
- The hidden Kho (warehouse) pages still use text buttons.
